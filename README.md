# Дневник PWA + API

Основной API работает на Ubuntu в Docker с SQLite вместо Cloudflare D1.
Установка рядом с Home Assistant и Nginx Proxy Manager, новые push-ключи
и переключение GitHub Pages описаны в [server/README.md](server/README.md).

Приложение получает профиль, оценки, расписание и домашние задания Дневник.ру по токену пользователя.
В окне «Ввести токен» нажмите «Найти учеников по токену» и выберите ребёнка и школу.
Можно также указать personId ребёнка и schoolId школы вручную.
ID не преобразуются в JavaScript Number: большие идентификаторы сохраняются строками.

## Локальный запуск

1. Установите зависимости: `npm ci` и `npm --prefix worker ci`.
2. В `.env.local` задайте `VITE_API_BASE_URL=http://localhost:8787` (без токена).
3. В одном терминале: `npm --prefix worker run dev`.
4. Во втором: `npm run dev`, затем откройте `http://localhost:3000/dnevnik/`.
5. Нажмите «Ввести токен». Вводится ID персоны ученика, а не пользователя родителя.

В интерфейсе выберите даты (до 31 дня) и нажмите «Обновить задания».
ДЗ отображаются с предметами, учителями и ссылками на вложения. Оценки связаны
с предметами, уроками, учителями и видами работ. Расписание показывает время,
кабинеты, темы уроков и ДЗ. Лента состоит из полученных оценок и заданий.
Выполнение отмечается только на этом устройстве и не отправляется в Дневник.ру.
В настройках доступны автообновление при открытом приложении и фоновые Web Push.
Сервер проверяет оценки каждые 5 минут. Токен и push-подписка
хранятся в SQLite в зашифрованном виде; ключ шифрования и VAPID-ключи — в `server/.env`.
В старом Worker Cloudflare Cron отключён.
Пользователь включает фоновую подписку отдельно и разрешает уведомления браузера.
При отключении/выходе серверный токен, подписка и очередь удаляются.
Подробная настройка: [server/README.md](server/README.md).
Первая загрузка и расширение дат на старые оценки не вызывают уведомлений.
Средний балл считается по загруженным данным и настройке uses_weighted_avg школы.
API не передаёт веса в этих ответах: при взвешенном среднем расчёт скрыт, вес не угадывается.

## Хранение

Обычное подключение хранит токен в sessionStorage до закрытия вкладки. Worker получает
его в Authorization и передаёт в Access-Token только на api.dnevnik.ru. При отдельном
включении фоновых уведомлений зашифрованная копия токена сохраняется в SQLite.
ID ученика/школы и последние ответы ДЗ, оценок и расписания хранятся локально для офлайн-просмотра.
При ошибке отдельного раздела остальные обновляются, а его предыдущие данные
сохраняются с отдельными датами последней успешной загрузки.
Кэш разделён по ученику и школе. Кнопка выхода удаляет токен и сохранённые данные.
Сервис-воркер не кэширует API-запросы. После истечения токена введите новый.

## API Worker

- `GET /api/health` — состояние сервиса, без авторизации.
- `GET /api/context` — ученики, школы и классы из контекста токена.
- `GET /api/diary?personId=...&schoolId=...&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` — данные дневника с предупреждениями по разделам.
- `GET /api/push/config` — доступность Web Push и открытый VAPID-ключ.
- `GET|POST|DELETE /api/push/subscription` — состояние, включение/обновление, отключение фоновой подписки.
- `POST /api/push/test` — тестовая отправка для зарегистрированного устройства.
- `GET /api/profile` — профиль владельца токена (может быть родителем).
- `GET /api/homework?personId=...&schoolId=...&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` — ДЗ ученика.

Для личных данных нужен `Authorization: Bearer <token>`. Ответы имеют Cache-Control: no-store.
Worker обращается только к фиксированным методам API; произвольного прокси нет.

## Проверка и публикация

```powershell
npm run lint
npm run build
npm --prefix worker run lint
npm --prefix worker test
npm --prefix worker run test:unit
```

Команда `test` запускает Cloudflare runtime. Если локальный workerd не запускается
(на этом Windows: write EOF), `test:unit` проверяет те же обработчики и преобразование
ответов в Node с подменённым API. Это не заменяет проверку развёрнутого Worker.

При публикации сначала обновите Worker: `npm --prefix worker run deploy`.
Проверьте адрес, выданный Wrangler: имя Worker в worker/wrangler.jsonc — `dnevnik`.
Для production-сборки задайте VITE_API_BASE_URL равным фактическому HTTPS-адресу Worker.
GitHub Pages публикует PWA из main через существующий workflow; он не развёртывает Worker.
Токен не должен попадать в .env, исходники, CI или параметры URL.
