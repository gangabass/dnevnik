# Фоновые уведомления об оценках

> Основной сервер перенесён на Ubuntu: см. [server/README.md](../server/README.md).
> Cloudflare Cron в `wrangler.jsonc` отключён. Ниже сохранена справка по старому
> развёртыванию; его расписание не следует включать одновременно с Ubuntu.

Cron `*/5 * * * *` запускает scheduled-обработчик каждые пять минут. Телефон не делает
фоновые запросы в Дневник.ру: сервер проверяет последние 31 календарный день, сравнивает
ID и значения отметок и отправляет Web Push. Метаданные предметов загружаются только
при изменениях; если они недоступны, уведомление всё равно содержит оценку.

## Серверная настройка

Worker называется `dnevnik`; база `dnevnik-push` привязана как `PUSH_DB`.
В этом проекте база и её ID уже указаны в wrangler.jsonc.

```powershell
cd worker
npm ci
node scripts/generate-push-secrets.mjs
npx wrangler d1 migrations apply dnevnik-push --remote
npx wrangler secret bulk .push-secrets.json
npm run deploy
```

Генератор создаёт `.push-secrets.json` и `.dev.vars`, не печатает значения ключей
и не заменяет существующий файл. Оба файла исключены из Git. Сохраните резервную
копию ключей в надёжном месте. Не генерируйте новые ключи при обычном развёртывании:
изменение TOKEN_ENCRYPTION_KEY сделает сохранённые токены нечитаемыми, изменение
VAPID-ключей потребует заново подписать устройства. VAPID_SUBJECT — HTTPS-адрес
владельца приложения или его mailto-контакт.

Для другого Cloudflare-аккаунта сначала создайте свою базу `wrangler d1 create
 dnevnik-push` и замените database_id в wrangler.jsonc. Для локальной проверки:

```powershell
npx wrangler d1 migrations apply dnevnik-push --local
npx wrangler dev --test-scheduled
```

## Включение на устройстве

1. Опубликуйте новую PWA и откройте её по HTTPS.
2. Введите действующий токен Дневник.ру и выберите ученика.
3. Настройки → «Включить фоновые уведомления» → разрешить уведомления браузера.
4. Нажмите «Тест». После приёма push-сервисом уведомление должно появиться на устройстве.
5. Закройте PWA: дальнейшие проверки выполняются сервером каждые 5 минут.

На iPhone/iPad требуется поддерживаемая версия системы и установка PWA на главный
экран. Доставка зависит от сети, разрешений, настроек энергосбережения и режима фокуса.
Время «Принято push-сервисом» не является подтверждением показа на экране телефона.

Первая подписка сохраняет исходные оценки и не рассылает историю. Обновление токена
для того же ученика сохраняет базу сравнения и очередь: оценки, пропущенные во время
истечения токена и попадающие в проверяемые даты, будут обнаружены после возобновления.
Смена ученика начинает новую базу сравнения и удаляет уведомления предыдущего ученика.
Каждое устройство имеет собственную подписку; текущая подписка следит за одним учеником.

## Хранение и надёжность

- Токен, браузерная подписка и содержимое очереди шифруются AES-256-GCM с отдельным
  случайным IV и привязкой шифротекста к устройству/назначению.
- На устройстве хранится отдельный случайный ключ управления подпиской. На сервере —
  только его SHA-256. Он позволяет проверить состояние и отключить подписку без токена.
- Снимок оценок и очередь записываются транзакционно. Аренда обработки защищает
  от перекрывающихся cron-запусков; результат старого запроса не перезаписывает новый токен.
- Ошибки API и push-сервиса повторяются с увеличением задержки. Недействительные
  браузерные подписки (404/410) удаляются вместе с токеном и состоянием.
- При 401/403 от API токен удаляется из базы, проверки приостанавливаются и ставится
  одно уведомление о необходимости переподключения.
- Уже принятые уведомления не создаются повторно обычной проверкой. При неопределённом
  сетевом результате повторная отправка возможна; стабильный tag одной версии отметки
  позволяет браузеру заменить ещё отображаемое уведомление. Строгой гарантии exactly-once нет.
- При активной фоновой подписке локальные уведомления открытой PWA подавляются.
- Выход сначала удаляет серверную подписку. Если сервер недоступен, ключ управления
  сохраняется и выход предлагает повторить удаление. Уже отправленное уведомление отозвать нельзя.

За один запуск обрабатываются до 25 устройств, по 3 одновременно. Для большего числа
активных пользователей потребуется увеличивать производительность и пересматривать
лимиты платформы; для небольшой персональной установки этой очереди достаточно.

После первой регистрации последняя успешная проверка появится в настройках после
ближайшего cron. Изменение расписания Cloudflare может применяться с задержкой.
Тестовые отправки ограничены одной в минуту на устройство.

## Проверки

```powershell
npm run lint
npm run test:unit
npm test
npx wrangler deploy --dry-run
```

Node-тесты используют настоящий SQLite в памяти и синтетические токены. Они проверяют
шифрование, базу сравнения, владение подпиской, повторную доставку, отзыв токена и
обработчик service worker. Реальная доставка проверяется кнопкой «Тест» на устройстве.
Не включайте секреты в логи, экспорт JSON, аргументы URL или коммиты.
